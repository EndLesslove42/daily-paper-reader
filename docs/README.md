## 定向补充：模块替代的边界与嵌回提速

本节根据用户当日提出的实际瓶颈追加：Transformer已经能够逼近CMAQ的Vd，但CPU推理慢，迁到GPU又涉及搬运、同步与原有MPI布局。新增两篇均为明确标年的方法补充，保留早间三篇，今日合计五篇；这次是人工指定的同日日报修订。

| 优先阅读 | 回答的问题 | 最应关注的位置 |
| --- | --- | --- |
| [Ukkonen, 2022，JAMES](https://agupubs.onlinelibrary.wiley.com/doi/full/10.1029/2021MS002875) | 哪一段值得替代，为什么小网络也可能更慢？ | 第3节的边界比较、第4.2节的速度测试 |
| [Ukkonen与Hogan, 2023，GMD](https://gmd.copernicus.org/articles/16/3241/2023/) | 如何保留物理求解器，在CPU中部署系数代理并做在线验证？ | 第2.3节的批量推理、第4.3节的IFS验证、第5节的效率讨论 |

两篇均保留宿主物理模型。第一篇含整个辐射参数化的对照实验，本次借鉴的是其子过程边界比较；第二篇只替换气体光学参数化，保留辐射传输方程。它们是同一研究路线的边界对照与在线验证，不是两项独立交叉证明。第二篇的ecRad约1.5倍加速来自离线模块计时，年度IFS实验验证的是在线模拟表现，不能混称IFS整体提速1.5倍。

筛选时除主题贴合外，还看优化后的物理基线、计时范围、公开代码和宿主模型验证。新增两篇分别发表于JAMES与GMD，也不单凭期刊名称保证结论成立；宁可选可靠的经典研究，也不为贴题或凑数放低证据要求。各篇局限明确列出未复现及迁移边界。

### 对当前Vd实验的具体启发（阅读判断，尚需实测）

1. **先确定整体加速上限。** 测出拟替代边界在原CMAQ总用时中的占比 f。若其核心计算加速 r 倍，而新增打包、接口、搬运和同步开销占原总用时 h，则简化估算为 S = 1 / (1 - f + f/r + h)。各项必须按互不重叠的范围计时。即使核心计算无限快，f只有5%时，无额外开销的整体上限也仅约1.053倍。这是示例，不是对当前CMAQ的测量。
2. **比较有物理意义的模块边界。** 至少对照“仅预测共享Vd通道”和“覆盖特征计算、阻力/交换系数到全部Vd输出的完整地表交换参数化”。后者仍可保留原浓度与通量更新；能否更快取决于是否真正移除了热点和重复计算。跨到沉降与近地层混合的联合模块，只应在剖析证明两者共同构成热点、且能定义守恒接口后再研究，不能为扩大边界随意合并过程。
3. **优先做CPU内的部署基线。** 用当前Transformer作为精度参照，比较小型MLP或蒸馏学生；模型只加载一次，预分配并复用缓冲区，在本地网格块内批量输出共享通道。静态/按月更新的遥感表征可缓存；随气象变化的动态特征仍按其物理更新节奏处理。减少数组转置、重复归一化和逐格点的小调用。这些是待验证方案，不保证比现有实现快。
4. **用完整调用成本判断GPU。** 单独统计特征准备、打包、CPU→GPU、推理、GPU→CPU、回填及等待，再比较模块与整次模拟总用时。保留现有MPI分域，先避免为了小型Vd网络额外全域gather；只有批量足够大或有合法的独立计算可重叠时，才可能抵消传输和同步。异步不能默认使用过期状态，也不会自动消除物理依赖。
5. **同时报告三个层次。** 核心网络推理、完整替代模块、完整CMAQ模拟分别计时。固定网格、步长、MPI布局、精度与I/O范围；CPU线程数明确配置，GPU带来的额外资源单独交代。精度则同时检查Vd、沉降通量/收支和多步浓度演化。

作为工程旁证，[TorchClim v1.0（2024）](https://gmd.copernicus.org/articles/17/5459/2024/)明确讨论CPU/GPU复制与MPI布局；其参考实现并未实现提速，CAM用时增加约20%。因此“能接进LibTorch”与“已实现提速”要分开验证。

另核查了近期的[OASIS3-MCT/Eophis耦合研究（2026-10-30）](https://gmd.copernicus.org/articles/19/10345/2026/)。它提供分布式和异步部署路径，但“不增加求解时间”以适当增加计算资源为条件，并不证明小型Vd代理放到GPU就能免费提速。本次作为相关工程背景列出，不另增加推荐条目。
